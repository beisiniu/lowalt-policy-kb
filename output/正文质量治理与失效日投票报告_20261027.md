## 一、问题：三类"看起来有正文、实际不可用"的文件

本次体检用四个客观指标判定每篇正文是否可信：汉字占比（汉字数 ÷ 总字符）、JS 关键词密度（每万字命中数）、HTML 标签数、PDF 字形编码残留（`/GXX` 片段）。

初次扫描 154 篇的结果：**合格 115 篇、存疑 11 篇、不合格 28 篇**——近四分之一语料存在问题。按成因分三类：

| 类型 | 典型表现 | 代表文件 | 后果 |
| --- | --- | --- | --- |
| **网页源码残留** | 汉字占比 6%~13%，正文里夹着 `!(function(){…})`、CSS 规则、备案号 | 武汉通告（64053 字 / 131 chunk）、东莞实施方案（107126 字 / 37 chunk）、绍兴 4151 通知 | 大量无意义切片，检索时命中 `function(){var ua=navigator.userAgent...}` |
| **页面框架文本** | 汉字占比 15%~25%，导航栏与页脚占了正文一半以上 | 上海适飞空域通告、天河暂停通知、光明暂停公告 | 切片里混入"首页 要闻动态 政务服务""主办单位：… 沪ICP备…" |
| **PDF 字形乱码** | 汉字占比 1%，正文是 `/G21/G22/G3A` 这类编码 | 北京 3 部试行文件（PDF 版，53 chunk） | 完全不可用；`pypdf` 与 `pymupdf` 均无法解码（字体子集化且缺 ToUnicode 映射） |

## 二、修复：50 篇正文重写 + 2 篇如实标注

### 2.1 清洗规则（`tools/body_quality.py`）

- **剥离源码**：按 `<script>` / `<style>` / 注释 / 标签的顺序清除，再还原 HTML 实体与 `\u0022` 这类 JSON 转义，最后按"整行无中文且含代码特征"逐行丢弃；
- **剥离页面框架**：只在文档后半段识别页脚标志（主办单位、ICP备、网站标识码、上一篇/下一篇等），避免正文中段的"地址：/联系电话"误切；头部跳过导航短行与面包屑；
- **达标线**：汉字占比 ≥ 0.55 且汉字数 ≥ 400；公告/通告/通知类放宽到 120 字（这类文书本身极短）；
- **PDF 乱码不尝试修复**：直接判定 `reject`，必须换来源。

### 2.2 浏览器重抓（`tools/fetch_by_browser.py`）

有 6 份靠清洗救不回来，改用 CDP 驱动真实 Chrome 渲染后取 `innerText`（渲染后的可见文本天然不含脚本与样式）：

| 文件 | 原状态 | 重抓结果 |
| --- | --- | --- |
| 北京 3 部试行文件（原 PDF 乱码） | 汉字比 0.011，53 chunk | 换网页版，4851 字，汉字比 0.84，三部规定全文齐全 |
| 北京市无人驾驶航空器管理规定（2026-11-15 施行） | 汉字比 0.079，16 chunk | 1509 字，汉字比 0.848，12 条全文 |
| 北京特殊保障规定（9 月修订版） | 汉字比 0.117 | 1806 字，汉字比 0.839，14 条全文 |
| 上海 2025 / 2026 版适飞空域通告 | 汉字比 0.154 | 352 / 420 字正文（通告本身就这么短） |
| 天河暂停实施通知 | 汉字比 0.133 | 360 字，正文完整 |
| 光明暂停实施公告 | 汉字比 0.039，22 chunk | 305 字（公告原文仅约 150 字，其余为元数据） |

> 关键约束：Chrome 进程在本环境的两次命令调用之间会被回收，因此"启动浏览器 → 逐个渲染 → 关闭"必须在同一次执行内完成。

| --- | --- | --- |
| 合格正文 | 115 篇 | **149 篇** |

## 三、建库质量闸（`build_chroma_db.py`）

修复是治标，闸门才是治本。建库脚本新增两道检查，不合格直接拒收并在 manifest 里留档：

| 闸门 | 判据 | 动作 | 记录字段 |
| --- | --- | --- | --- |
| 正文质量 | `body_quality.judge()` 返回 `reject`（汉字占比 < 30% 或 PDF 乱码 > 50 处） | 不入库 | `manifest.rejected_bodies` |
| 切片爆炸 | 单篇切片数 > `--max-chunks-per-policy`（默认 250） | 不入库 | 同上 |

建库输出会打印被拦清单，例：

```
⚠ 正文质量闸拦下 3 篇（明细见 manifest.rejected_bodies）：
    - 云南省 / 云南省支持低空经济健康发展的若干措施：汉字占比过低，正文实质为源码
```

这次实际运行中，第一次重建拦下 3 篇（云南若干措施、低空保险实施意见、天津港保税区方案）——它们不在原 manifest 里，所以第一轮修复没扫到。补齐后第二次重建 **0 拦截**。

## 四、失效日三模型投票（B 级 19 份）

### 4.1 为什么要投票

`tools/infer_validity.py` 让单模型判断 83 份无失效日文件，按证据硬度分成 A/B/C 三级。A 级 23 条证据可逐字核对、日期与区间末年对齐，可直接采纳；**B 级 19 条属于灰区**——给了日期但未过全部门槛，多为"只有规划期、年份疑为目标年"。单模型在这种灰区上容易受提示词措辞影响，因此引入 DeepSeek / Qwen / GLM 三家独立判定，各投一票（互不可见）。

### 4.2 投票规则

- 主票 = 判定类型（`explicit_expiry` / `plan_period` / `open_ended` / `repealed` / `unclear`），副票 = 具体日期；
- 两者都被 ≥2 家认同才算采纳；
- 3/3 一致 → **一致采纳**；2/3 → **多数采纳**；三家各不相同 → **判定分歧**，不采纳日期。

### 4.3 结果（19 条 × 3 模型 = 57 次判定）

| 裁决 | 条数 | 处理 |
| --- | --- | --- |
| 一致采纳（3/3） | **8** | 直接写入覆盖表 |
| 多数采纳（2/3） | **7** | 写入并记录分歧 |
| 判定分歧（1/1/1） | **4** | 不采纳日期，按长期有效处理 |

**采纳的 7 条日期**：

| 政策 | 失效日 | 票型 |
| --- | --- | --- |
| 加快推进低空制造产业高质量发展行动方案 | 2027-12-31 | 3/3 |
| 辽宁省低空经济制造业高质量发展三年行动计划 | 2027-12-31 | 3/3 |
| 中国民用航空局关于监管服务有关事宜的公告 | 2026-11-26 | 2/3 |
| 长沙市推动低空经济高质量发展实施方案 | 2026-12-31 | 2/3 |
| 青岛市促进低空经济高质量发展实施方案 | 2026-12-31 | 2/3 |
| 徐州市"低空+"场景应用创新行动方案 | 2026-12-31 | 2/3 |
| 浙江省高水平建设民航强省若干意见 | 2027-12-31 | 2/3 |

**8 条被三家一致判定为"长期有效"**（不设失效日）：低空经济标准体系建设指南、信息通信支撑低空基础设施实施意见、加快推动低空经济高质量发展实施意见、低空保险实施意见、四川促进低空经济发展指导意见、扬州低空经济发展实施意见等。

> 这是本轮最有信息量的发现：**单模型倾向于给"意见/纲要/指南"类文件硬凑一个日期，三家独立判断后集体回到"长期有效"**。B 级里一半以上是单模型的过度推断。

**4 条判定分歧**（山东无人机方案、济南实施方案、海珠工作方案、长治工作方案）：DeepSeek 判长期有效、Qwen 判有规划期、GLM 判无法确定。这类文件正文确实只有目标年而无明确期限，按长期有效处理更稳妥，已在覆盖表记录分歧与三票明细。

## 五、一个必须知道的连带影响

**v9 评估结果对应的是旧库（3710 chunks），不是现在这个库（3248 chunks）。**

本轮清理掉 462 个低质量切片、修好 39 篇正文，检索分布已经改变。v9 的"Naive 毒化 38.5% / Temporal 0%"不能直接套用到新库上——**要让结论对应新库，需要重跑 v9**（约 55 分钟）。这一点已写入 README 的待办。

同理，`data/national/benchmark_v9.json` 里若有题目的 `old_clause_id` 指向被清理掉的切片，重跑时需要重新校验；不过本次清除的都是垃圾切片，正式政策条款的 chunk 未被删除。
