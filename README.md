## 1. 项目要解决什么问题

把全国低空经济政策（国家条例 / 部委规章 / 省市措施 / 区县细则）做成可检索、可问答的知识库。难点在于**政策有时效**：某地 2023 年补贴"每平方米 50 元"，2025 年调整为 20 元，两份文件都在库里——直接向量检索会把旧条款排在最前（字面更相似），大模型照抄就输出错误答案。

本项目的解法是**双分支架构**：

```
            ┌─► Naive 分支：   检索 Top-5 ─────────────────► 大模型直接答     （对照组）
用户问题 ───┤
            └─► Temporal 分支：检索 Top-5
                    │
                    ├─ 时序门禁：逐条款判定 status / valid_from / valid_to vs 查询日
                    ├─ 过滤：    失效条款剔除（或降权，消融用）
                    ├─ 路由：    有存活条款→作答 / 无→明确拒答
                    └─ 三裁判：  DeepSeek + Qwen + GLM 多数票判卷（评估用）
```

**四个发现**：

1. **Temporal 毒化率在全部 20 个 k 上恒为 0**——架构有效性不依赖 k。这是整个结论里最需要稳健性的部分，它在 20 个点上都稳住了。
2. **严格拯救率由"现行条款召回率"决定，不由 k 直接决定**。召回率是一条 S 形曲线：k=4 时 38.7%、k=8 时 87.1%、k=13 后封顶 96.8%；拯救率跟着走（25.0% → 65.0% → 70%±）。**k=1/2 时拯救率为 0 且拒答 100%，因为过滤后一条条款都不剩——"过滤后答不出"的瓶颈在检索，不在过滤逻辑。**
3. **Naive 毒化率没有随 k 单调上升，反而在 k=2→9 从 80.7% 降到 64.5%**，之后在 64.5%~71% 之间波动（这个波动幅度约等于单裁判噪声）。逐题比对 k=3 与 k=15：5 道 POISONED→CORRECT、2 道 REFUSED→POISONED。机制是候选变多后现行条款也进了上下文，模型有对照更容易选对——**毒化的充分条件是"旧条款在场且无对照"，单有旧条款不足以致毒**。
4. **k≥8 之后，拯救率在 65%~82% 之间无趋势波动，而召回率已饱和在 96.8%**。这个缺口（约 20 个百分点）不是检索问题，是"有条款但模型仍答错/拒答"，属于判分噪声与生成行为，加大 k 无法改善。

**k 的选取（判据与结果）**：

- **判据：现行条款召回率 ≥90% 且旧条款穿透率 ≥90%，取满足条件的最小 k。**
- **结果：k=9**（召回 90.3% / 穿透 96.8%）。最小 k 优先，因为上下文更短、推理成本更低、更接近真实部署配置。
- 为什么不用准确率挑 k：准确率受裁判噪声影响，在同一测试集上按准确率挑 k 等于在测试集上调超参数，会高估效果。检索层指标只由向量检索决定，同一 k 下完全可复现，适合作为选择依据；准确率只用于**验证**。
- 若更看重拒答率（用户体验），k=12~17 把拒答压到 19%~26%，代价是上下文翻倍。论文主表建议报 **k=9**，附录给这条曲线与 k=12/17 的对照。

| | T1（现行，应答"能"） | T2（失效，应答"不能"） |
|---|---|---|
| Naive | AFFIRM 15/18 = **正确率 83.3%** | AFFIRM 15/18 = **毒化率 83.3%** |
| Temporal | AFFIRM 14/18（正确 77.8%） | DENY 0 + OTHER 15 = **安全 83.3%**，AFFIRM 3 = 毒化 16.7% |

**断崖实锤**：Naive 在 T2 的毒化率（83.3%）与它在 T1 的正确率（83.3%）完全对称——同一批题、同一模型、只隔两天，它不知道时间流逝了。Temporal 在 T2 的 83.3% 全部转为安全行为（拒答），毒化仅 3/18（其余 3 例是 Top-9 中存在同地区其他现行补贴条款被模型引用）。

## 3. 出题方法论（2026-10-28 重做，交接必读）

这一节是本项目的核心方法论，也是 2026-10-28 之前的最大缺陷所在。

### 3.1 为什么废弃 v2 的出题方式

v2 的提示词是：给一对条款，先判断"A 与 B 是否构成实质差异"，若构成则"设计 1 到 3 道题"。

问题出在这两件事**可以各自做对、合起来却脱靶**：

- 判断"有实质差异"是**文段级**的操作——两条条款确实在某处不同；
- 出题是**题目级**的操作——LLM 完全可以出一道问在"另一个点"上的题，而那个点上 A 与 B 恰好相同。

结果是"旧条款全程陪跑"：题目读哪一版都能答对，旧条款进不进 Top-5 不影响结果。这类题占了旧题库的 82%。

更隐蔽的是它在数据上的表现：v2 的 28 道题覆盖 8 个地区，看起来覆盖面不错；但逐题检验后，**有效的那 5 道只来自 3 个地区**（黄埔 3、张家界 1、龙岗 1），武汉 6 道、芜湖 3 道、无锡/江苏/福州各 1 道全部无效。

### 3.2 v3 的三步式契约

`build_benchmark_v3.py` 的 `GEN3_SYSTEM` 把一次出题拆成三步，核心是第二步：

```
① 契合度分级
   High  ：同一事项（同主体、同事项），且对同一问题 A 与 B 的答案会不同
   Medium：同一事项，但答案相同，只是表述/体例/条款序号变化
   Low   ：不是同一件事，或无法就同一问题作答

② 仅 High 才列冲突点，每条必须写成成对答案：
   {"issue": "...", "a_answer": "按旧条款会得到的答案", "b_answer": "按现行条款的答案",
    "a_quote": "旧条款原文逐字摘录", "b_quote": "现行条款原文逐字摘录"}
   两条答案实质相同 → 这一条作废

③ 每个冲突点出 1 道题。题数 = 有效冲突点数，不设上下限
   冲突点为 0 → 一道不出，这是正常结果
```

**关键设计：冲突点自带可机械验证的证据。**

- `a_quote` 必须逐字出现在旧条款原文里，`b_quote` 必须逐字出现在现行条款原文里（脚本用 `find_span` 定位字符区间）——**编不出来**，原文里没有那句话就找不到。
- `a_answer` 与 `b_answer` 经 normalize 后必须不相等、不互相包含、bigram Jaccard < 0.85。
- 题目必须指向一个有效冲突点；`answer_type` 限定 `numeric` / `boolean` / `enum` 三类，**禁用 text**（使 90% 的题可机械判分）；题干 ≤ 60 字，禁泄漏词、禁年份、禁政策名片段。

因此每题落盘都带 `bait_evidence` 字段（旧条款会答什么、依据哪句原文、毒化机理），不需要再做事后"毒饵有效性"检验。`tools/check_bait.py` 保留为**独立复验工具**（用另一套判据交叉验证），不再作为闸门。

毒化机理三分（`bait_evidence.mechanism`）：

| 机制 | 含义 | v3 分布 |
|---|---|---|
| `contradiction` | 旧条款明确规定了相反结论（旧版要求 5 人团队，新版不要求） | 27 |
| `omission_b` | 冲突来自现行条款的沉默（旧版要求 5 人，新版未提人数） | 5 |
| `omission_a` | 冲突来自旧条款的沉默（旧版未设上限，新版设 200 万上限） | 0 |

### 3.3 资料利用率（回答"为什么题这么少"）

64 对候选条款对的实测结果：

| 环节 | 数量 | 比例 |
|---|---|---|
| 语料 chunks | 3166 | — |
| 失效条款 | 421 | 100% |
| 进入配对候选（词面相似度 ≥0.12，每条旧条款最多配 2 条新条款） | 64 对 | — |
| 分级 High | 24 对 | 37.5% |
| 分级 Medium | 5 对 | 7.8% |
| 分级 Low（不是同一件事） | 35 对 | 54.7% |
| High 但列不出有效冲突点 | 3 对 | — |
| 冲突点：原始 → 有效 | 53 → 42 | 79.2% |
| 题目：原始 → 有效（机械校验） | 51 → 41 | 80.4% |
| 独立复验通过 | **32** | 78.0% |

平均每个 High 对能挖出 **2.0 个**冲突点（最多 4 个）。这说明"挖掘深度"还有余量：旧口径平均每对只出 1.3 道题。

### 3.4 地区瓶颈（当前最大的限制）

复验通过的 32 道只覆盖 **3 个地区**：广州黄埔 26、张家界 3、深圳龙岗 3。

这不是出题能力问题，是**资料结构**决定的：421 条失效条款里，只有

1. **广州黄埔**——有完整的新旧两版措施（2024 版 + 2025 版），可逐条对比；
2. **张家界**——废止通告（旧条款说能领补贴，现行通告说该条款已废止）；
3. **深圳龙岗**——修订版措施；

这三处能构成"同一事项、结论不同"的对照。其他城市的失效条款多是零散单条，配不到同事项的现行条款。

**这也解释了旧题库的表象**：v2 的 8 个地区里，武汉/芜湖/无锡/江苏/福州出的题全部是无效毒饵——它们能凑出题，但凑不出冲突。

论文写作含义：建议把"有效新旧对照仅存在于 3 个地区、421 条失效条款中只有 N 条可构成实质冲突"作为**局限性说明**，同时把它转化为贡献——低空政策的时序问答是典型的低资源任务，本项目给出了可复现的利用率核算方法。

- 显式传 `--chroma-dir ./chroma_lowalt --embedding-function bge-zh`（默认值连的是别的库）

- **出题不要写"出 N 道"**：v3 的经验是，一旦给数量下限，LLM 就会凑题，凑出来的题毒饵无效

## 7. 质检体系

**失效文件入库三关**：

1. **官方失效证据链**：每条覆盖表带 evidence（原文引句）+ evidence_url；优先级：文件附则明文 > 政府网页"(失效)"标注 > 政策平台结构化字段（青岛政策通"是否长期有效"）> 提案答复确认 > 规划期推算（标"推算"）
2. **低空实质核查**：失效文件必须含低空飞行应用实质条款
3. **口径对齐**：边界问题先问用户再固化，不要自行收紧

**题库四关**（v3 新增后两关）：

1. **契合度分级**：Low 直接不出，Medium 不出（或出负对照）
2. **冲突点自证**：`a_quote`/`b_quote` 逐字命中原文 + 两答案实质不同（机械校验）
3. **题目机械校验**：无泄漏词/年份/政策名片段、金标证据在现行条款内、数值题数字在证据内、题干 ≤60 字
4. **独立复验**：`check_bait.py` 用另一套判据交叉验证，只保留通过的题

**机器检查**：`status_tracker.py --check`（已到期未改标 / 统计不一致）

**用户抽查**：北京禁飞、青岛通航、宝安状态、19 城 vs 17 双全、**出题是否真的用到旧条款**——用户点名核查是发现疏漏最有效的机制，交接后建议保持。

## 8. 踩过的坑（重要经验）

### 8.1 出题与评测（2026-10-28 新增，最贵的一课）

| 坑 | 表现 | 解法 |
| --- | --- | --- |
| 用数量下限逼 LLM 出题 | "设计 1-3 道"→82% 的题旧条款陪跑 | 题数 = 有效冲突点数，允许 0 道 |
| 让 LLM 事后自证 | 让它写"按旧条款会怎样"，它会编一条原文里没有的引文 | 引文必须逐字命中原文（机械可验），不能只靠它自述 |
| 把 N/A 当 0 | false_premise 题没有旧条款 → `clause_matches` 恒 False → 穿透率被稀释 | 按题型分轨，或拆表 |
| 用统一门槛卡答案长度 | boolean 题的"不能""不需要"被"答案过短（<5 字）"误杀 | 按 answer_type 分档 |
| 认为题目多就等于覆盖广 | 8 个地区 28 道题，实际有效仅 3 个地区 5 道 | 用毒饵复验逐题核，不看名义覆盖 |
| 静态判定偏严 | repeal 类题（旧条款说能领）被判"条款无关" | 交叉验证取并集，或人工抽检 |

### 8.2 采集与解析

| 坑 | 解法 |
| --- | --- |
| 深圳/民航局 TLS 报 BAD_ECPOINT | requests 失败降级系统 curl（Schannel 能握手） |
| 政府页 JS 渲染 | browser-automation-cdp；**启动+渲染+提取必须同一次调用**（Chrome 跨调用被回收） |
| PDF 扫描版 | pypdf 提不出字；找官方文本版，勿用 OCR 硬啃 |
| 公报合刊 PDF | 按"总体要求句→自印发之日起施行"截取单文件 |
| 合集页混入目录 | 条款区间法（第一条→施行条款） |
| 北京日报 APP 页混入 JS | 按正文结束标志截断 |
| 微信公号正文 | 取 `#js_content` 节点，iPhone UA |
| GLM 思考吃掉输出 | max_tokens 提到 5000；中文判定→归一化映射 |
| 征求意见稿 ≠ 正式文件 | 宁可不入不可超前 |
| 同名 DUP 挡新文件 | `policy_name` 加版本后缀 |

- 标准答案由 LLM 撰写，未经人工复核

- 题型偏补贴类（subsidy_changed 占 53%），因补贴条款在新旧两版中对应关系最完整
- 扫描版 PDF 无法入库
- 失效标注依赖公开渠道，存在滞后（实际执行可能延续，如宝安案例）

## 10. 给接手人的三句话

1. **先跑 `python tools/status_tracker.py --check`**——看有没有到期未改标的，这是数据正确性的底线；再读 `output/政策状态跟踪清单.md` 了解时间线上正在发生什么。
2. **改数据走覆盖表，不要改 extracted json**；URL 用 manifest 里的实际 source_url；改完重建库（3 分钟）。
3. **出题前先问"这道题旧条款会答错吗"**——答不出具体错法的题不要入库。v3 的 `bait_evidence` 就是为这件事存在的；口径问题（什么算低空、什么算失效）先问用户再动手，本项目两轮重大返工都源于自行收紧口径。

## 11. 版本库与 GitHub（2026-10-28 初始化）

本目录已初始化为 git 仓库，默认分支 `main`。初始提交包含代码、语料 txt、打标 json、题库、评估结果、图表与文档。

**不入库的内容**（`.gitignore` 已配置）：

| 内容 | 原因 | 如何恢复 |
| --- | --- | --- |
| `.env` | 三家 API Key | `cp .env.example .env` 后填 Key |
| `chroma_lowalt/` | 398MB 向量库，超出常规仓库体积 | 从本快照复制；或按 §6 重建（约 3 分钟） |
| `models/` | BGE ONNX 模型，约 24MB | 首次运行 `--embedding-function bge-zh` 自动下载 |
| `kb/index*/`、`data/_chroma_test/` | 可重建的本地索引/测试库 | `python kb_ingest.py ... --rebuild` |
| `*_backup_*.json`、`*.bak*`、日志 | 自动备份与运行产物 | 不需要恢复 |

**重建向量库**：

```bash
$VENV build_chroma_db.py --extracted-dir data/extracted_national \
    --chroma-dir ./chroma_lowalt --collection lowalt_policy \
    --embedding-function bge-zh --rebuild
```

> `data/extracted_national/*.json` 的 `_meta.source_file` 记录的是原始绝对路径。`build_chroma_db.py` 与 `kb_ingest.py` 已加“路径失效时按文件名回退到 `data/national_policies/`”的逻辑，换机或迁移后仍可重建。

**推送到 GitHub**（先确认 `.env` 不在 `git ls-files` 中）：

```bash
git remote add origin https://github.com/<你的账号>/<仓库名>.git
git push -u origin main
```

若初始提交使用了占位作者，先改成你的 GitHub 身份再推送：

```bash
git config user.name  "你的名字"
git config user.email "你的邮箱"
git commit --amend --reset-author --no-edit
```
